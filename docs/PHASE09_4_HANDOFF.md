## Operator handoff

1. **Startup architecture.** A detached local supervisor starts four existing services: the one-process source API, read-only MCP service, existing control host with Phase 09.1 controls, and a Vite production preview. It owns child process groups, persists non-secret PID/identity metadata, checks occupied ports and metadata locks, waits for readiness and cleans up its children on startup failure. No new agent framework or worker is added.
2. **Commands.** `./scripts/demo init --yes` creates a new dedicated database only. `start`, `status`, `prepare`, `check`, `reset --scope …` and `stop` are supported. Global port/path options precede the command and are persisted per harness directory. A healthy repeated start is a no-op. Each configuration builds its own frontend output bound to its actual source URL; starting a second preview does not overwrite the first preview's assets.
3. **Runbook.** [DEMO_RUNBOOK.md](DEMO_RUNBOOK.md) is authoritative for setup, actual URLs, personas, the four scenarios, Concierge, Operations, reset, fallback and shutdown. Older handoffs retain their historical startup instructions.
4. **Personas.** Program operator initiates the four cases; Engineering approver owns CR-017 authorization/evidence adequacy; Program Owner owns exact recovery metadata and delivery commitments; Read-only viewer inspects. Existing UI switching stays explicit. There is no Quality-release persona or production authentication.
5. **Pre-demo checks.** `check` requires healthy services, five source reads, all four canonical cases, a valid `phase09-v1` baseline, no stale/unverified decision or active work, consistent reset state, installed Concierge/runtime, configured model credentials and inactive background execution. It returns nonzero when any gate fails. `status` is informational and explains discrepancies. Credential presence is not provider connectivity or access verification.
6. **Reset integration.** The helper delegates to the existing Phase 09.1 CLI/HTTP operation, retaining scope preview, confirmation, epoch, shared-dependency guards, archive policy and independent readback. Startup never calls reset. Source restore and host reconciliation remain separate commits. Full/scenario UI controls remain unchanged.
7. **Fallback.** No fake connected answer or automatic mode switch is introduced. Announce **Recorded demo** and use the [existing gallery/record index](PHASE09_4_RECORDED_FALLBACK.md). Historical failed live runs remain failures. Returning to the live workbench is explicit; resetting is a separate choice.
8. **Performance.** Source-app code is loaded only for source routes. Operations rendering is lazy; lightweight shared search/alert/run-link helpers remain separate. Overview fetches no Operations/eval dataset on initial load. Hidden tabs pause expensive host case polling, while demo epoch invalidation continues and focus refreshes current state. Existing loading and action states remain intact; lazy-load failure now has a readable recovery panel.
9. **Bundle result.** The previous 513.48 kB main entry is about **268.5 kB** after splitting (roughly 48% smaller). Source apps are about 236.8 kB, the control app about 249.4 kB and Operations about 19.3 kB. No chunk exceeds 500 kB and the advisory is gone. No dependency or framework was added. Exact final build output is in the verification manifest.
10. **Console/network cleanup.** The production browser tour found a missing favicon; an explicit local SVG removes that 404. The source-only foundation browser configuration now points to a dedicated unavailable host port, avoiding accidental reads of a working operator host. Legitimate service failures remain visible. The cold-start tour records zero normal-route console warnings/errors, failed requests or failed HTTP responses; the deliberate lazy-asset failure is separate and recovers on reload.

## Implementation and boundaries

The executable wrapper is [scripts/demo](../scripts/demo). The supervisor is [control_host/demo_harness.py](../src/program_coordinator/control_host/demo_harness.py), inside the host-only namespace. The existing architecture test still prohibits subprocess/source access in the agent runtime; it was not relaxed. Initialization imports existing source-owned seed/install functions only for a missing `.demo/` file. Reset exclusively delegates to Phase 09.1.

The additive `GET /control-api/readiness` observes installed model/credential configuration, active workflows/host tasks/Concierge turns and absent background workers. It uses the existing local boundary and trusted read scope. It creates no workflow, conversation, approval or source record, and is not an agent/MCP tool. Credential values and arbitrary error prose are never returned. Source API, MCP permissions, agent prompts, exact approval/execution services and eval graders are unchanged.

Default operator data is intentionally separate from old working databases. Supplying an existing source/metadata pair is explicit. Symlink/hard-linked file targets and out-of-storage paths are refused. `stop` validates the recorded supervisor identity/token and signals only that supervisor; child cleanup uses its actual subprocess handles. It never kills by port. If external force-kill destroys ownership evidence, the helper refuses unsafe cleanup and the runbook describes manual recovery of known processes.
