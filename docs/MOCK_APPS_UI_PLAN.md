# Mock application UI plan

Authorized phase: five local source-system applications in one React/TypeScript/Vite
project. Preserve the existing SQLite state, four POST contracts, public mock roles,
fixed scenario clock, business-document allowlist, and read-only Manufacturing/ERP.
Historical foundation specifications remain intact. No AI runtime or hosted service.

1. Baseline: existing pytest suite **172 passed in 25.66s**, no skips; independent
   scenario validation passed (42 records, 110 references, six documents, nine options).
2. Add five authenticated, scope-enforced discovery GETs: changes, units, lots,
   orders, and programs with existing customer/supplier names and scenario context.
   Test read-only behavior, identity/scope, and record fidelity; export OpenAPI.
3. Generate TypeScript schemas from actual OpenAPI. Build a shared HTTP client,
   tab-scoped explicit persona, refresh/focus revalidation, persistent retry metadata,
   accessible shell, record links, safe Markdown, and domain-specific navigation.
4. Engineering: change worklist, baseline/request comparison, evidence/configuration,
   documents, immutable plan authoring, exact-plan engineer decision, audit history.
   Validation: evidence, options, samples, slot/reservation schedule, approved booking.
   Manufacturing: provenance and independent holds. ERP: authoritative commitments
   and approved rates. Planner: baseline/conditional forecast, dependencies and linking.
5. Verify the real four-step HTTP workflow in Playwright using an isolated database;
   prove cross-tab persistence, direct API changes, denials, retry recovery and unchanged
   commitments/restrictions/evidence. Run backend regression, TypeScript and build.
   Inspect screenshots at 1440×900 and 1280×800; document actual results and limits.

Visual direction: compact desktop workspaces with a dark shared navigation rail,
white operational surfaces, readable tables and restrained per-app accents. Each app
has its own working layout. No fabricated charts or records; genuine empty states.

Integration notes: actual responses embed plans on changes, reservations on jobs,
and tasks on links. Options already provide full expected source versions and computed
eligibility/timing/cost. A late resource-eligible option remains selectable. Program
directory context exposes only named business context fields, never arbitrary metadata.
No scenario contradiction found. The historical no-frontend restriction is superseded
only for this explicitly authorized phase.
